# Capture Selection release qualification

This matrix qualifies MEM-189 through MEM-191 on the signed, notarized release candidate. Record the macOS version, source commit, app version/build, notarization submission ID, and result for each row in the release issue. Test the default Control–Option–Shift–Space shortcut and at least one customized shortcut.

| Surface | Required coverage | Expected result |
| --- | --- | --- |
| Native text | TextEdit plain/rich text, Notes, Safari text, Mail compose/read views, and Xcode source | Only the explicitly highlighted accessible text is appended to the persistent Draft, separated by one blank line. The existing Project destination remains selected and the editor opens focused at the end. |
| Browser text | Safari and Chrome page text, editable fields, and contenteditable fields | Accessible selected text is captured; unselected page text is never captured. Browser behavior that does not expose `AXSelectedText` produces the generic no-selection toast. |
| Non-text and empty | Images, PDFs without selectable text, canvas content, blank/whitespace selection, and no selection | The Draft is unchanged, the capture popover does not open, focus is not stolen, and an accessible five-second toast appears. No automatic retry occurs. |
| Secure fields | Password and other `AXSecureTextField` controls | No text is returned or persisted. The generic no-selection toast appears and no selected value occurs in system/app logs. |
| Permissions | Accessibility denied, first invocation, later invocation, grant, revoke, and relaunch | Status in Settings is accurate. The first denial produces the one-time alert; later denials use an actionable toast. Permission prompting occurs only after an explicit action. Revocation takes effect on the next invocation. |
| Limits and repetition | Empty Draft, populated Draft, exactly 50,000 combined characters, 50,001 characters, repeated rapid invocations | Valid captures persist atomically. Oversize capture leaves the Draft byte-for-byte unchanged. Concurrent invocations do not overlap or duplicate one provider result. |
| Shortcut settings | Configure each shortcut independently, introduce conflicts, restore each default separately, relaunch | Failed registrations preserve the active shortcut. Both shortcuts persist independently. Restore controls affect only their matching shortcut. |
| Accessibility | Full Keyboard Access, VoiceOver, Reduce Motion, light/dark and increased contrast | Recorders, status, alert, toast, action, Draft editor, and errors have meaningful labels/order. Success and failures are announced. No required information depends only on color or motion. |
| Isolation | Attempt connection from an app with a different identifier/signature; interrupt and invalidate the helper; delay beyond one second | Unauthorized clients are rejected. The Draft is unchanged on every communication/authentication/timeout failure and only generic UI is shown. |
| Release bundle | Inspect app/helper signatures, entitlements, hardened runtime, notarization, stapling, and Gatekeeper | Main app is sandboxed. Helper is embedded in `Contents/XPCServices`, unsandboxed, has no unrelated entitlements, and has the same Developer ID authority. All automated release gates pass. |
| Update and rollback | Update from the previous signed beta with an existing selected-text Draft/settings, then exercise rollback procedure | Sparkle replaces the signed app and helper atomically and preserves Draft/settings. A bad release is withdrawn by restoring the last known-good signed appcast and publishing a fixed higher build; bundle components are never mixed manually. |

Before approval, run `swift test`, the Xcode build-for-testing/UI suite, `Scripts/release/test-release-scripts.sh`, `Scripts/release/verify-product-release.sh`, the signed-app verifier, notarization/stapling/Gatekeeper gates, and the clean staged Sparkle update exercise. Search unified logs and retained CI output for fixture selection text; any occurrence blocks release.
